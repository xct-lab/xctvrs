# XCTVRS site and Cloudflare deployment

The approved public site is generated by `python3 scripts/build-site.py` into `dist/`, using the styles and icon in `assets/`.
The build produces the homepage, VRS issues, petition draft, community plans, CRTC/CAV information, evidence approach, resources, updates, about, participation-status page, and a 404 page.

The source here reproduces the 14 files deployed to https://xctvrs.ca/ during the approved three-domain architecture update.
Legacy root HTML pages remain preserved in the repository but are not deployment inputs.

## Scope

XCTVRS is the canonical VRS advocacy project. DUN360 links here for VRS advocacy; XCT.Guru presents technical development plans.
The petition is visibly a draft; no signature collection, accounts, surveys, or working groups are active.
Private records, complaint references, correspondence, internal handoffs, and unverified scorecards are excluded from the site build.

## Manual GitHub deployment

The workflow runs only through workflow_dispatch on main; a push or merge does not deploy.
After review and merge, configure these repository Actions secrets:

- CLOUDFLARE_ACCOUNT_ID: the account containing the xctvrs project.
- CLOUDFLARE_API_TOKEN: a Cloudflare token with Account > Cloudflare Pages > Edit permission, restricted to that account.

Save tokens directly in GitHub Secrets, never in source or chat.
Local Wrangler login does not authenticate Actions.
Run the workflow only when a deployment is intended. It uploads dist to the existing xctvrs Pages project's production branch main.

The native Git provider field in Cloudflare remains empty because Actions uses Direct Upload.
[Cloudflare CI documentation](https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/).
